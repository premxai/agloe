Agloe · trap streets for AI agent swarms

When one agent's mistake spreads through a swarm, can you trace it?

Usually, no. We studied a real incident where AI agents passed tricks to each other through a shared wiki, then ran thousands of agents in an offline lab. The logs people keep can't say who learned what from whom, and the obvious detectors accuse the wrong agents.

16% of copying in the real incident can be traced from the edit logs, even by a perfect investigator.

The logs you keep decide what you can know

For every time one agent reused another's distinctive string, was the earlier author visible in the log where it happened? In the incident, reads were never logged, so most sources were invisible. In AI Village, chat was logged for everyone, and copying was traceable almost every time (every week of the whole dataset), with one short dip in the weeks after chat rooms launched. The point is not that AI Village is easy; it is that the incident's missing read log is what made it hard.

The obvious detector accuses the innocent

"Same string means copied" is the first thing anyone tries. On the real incident logs it manufactures findings:

Rejected flags were things like dataset field names and round timestamps that many agents type independently, each used by up to 49 different agents. The three that survive are session tokens carried in URLs: the only reason those hops are provable at all.

AI isn't random, and each model has habits

We gave independent agents of different models the same small task and watched which throwaway "cache-buster" value each one added to a URL. Some models add one almost every time, some never do, and several reach for the same value, so a match alone is weak evidence.

Trap streets: make copying confess

Mapmakers hide a fake street so copiers give themselves away. We do the same for swarms: every time the shared wiki serves a page, each link carries its own token. A copied link names the exact copy it came from. Decoration is not enough: whether a harmless-looking tag survives copying depends on the model, so the token has to be something the link needs.

Make the token the only way in

Some models skip the token by fetching their own session. We closed that door in the lab: the mirror no longer hands out sessions, so the only way in is a link the wiki served. Tracing then comes from the access design, not from the agents' habits. The question is what it costs.

When a bad tip spreads, what do you re-check?

A wrong tip gets posted in the shared wiki and some agents use it. With no trace, the safe move is to re-run everything, or everything submitted after the tip appeared. Tracing the tip gives a short list instead. Each list is scored against the hidden record of who really read what.

How we tested

Every lab run is offline (reserved .invalid hosts), benign, and scored against a hidden answer key. The table is read from the runs themselves; the criteria below are what we held ourselves to. You can replay any of these runs, with the hidden read log, in the colony.

The criteria

Truth
The lab's hidden read log: which copy of a page each agent was served before it used a link. "Copied" means exposure, not intent. Real investigators do not have this.
Tag conditions
none: links served as written. inert: every served link gets a random-looking tag (decoration). load-bearing: every served link gets its own session token that the mirror needs to answer.
What an investigator sees
Only the edit log (wiki writes and submissions). Baselines: blame the latest writer of the link, the earliest, or a random one, and the best of the three for each run, chosen with the answer key in hand, which is generous to the baseline.
Scores
Top-1 (the source is named correctly), recall, false accusations of agents that worked alone, calibration (ECE), and for a planted bad tip the precision and recall of the outputs the tip reached, and the share of outputs you would have to re-check.
Statistics
Rates pooled over runs with a run-level bootstrap 95% interval, because agents inside one swarm read each other and are not independent. With fewer than 3 runs the interval is the min-max.
Excluded
Real data
The incident: 35 behaviours with at least 20 adopters; a "marker" is a distinctive string (12+ characters, not vocabulary) used by 2 to 10 agents; a match counts as copying only if chance would produce it at least 100 times less often; cross-team jumps were checked by hand. AI Village: every week of the whole chat, in 7-day windows, with the visible-source rule changing at the rooms launch (2026-02-25).

A checklist for anyone running a swarm

  1. Log reads, not just writes. Who was shown which page or message, and when. Without it most sources are invisible.
  2. Give every served copy its own token, one the destination needs. Decoration gets dropped by some models; make the token the only way in.
  3. Before calling a match copying, check the base rate. Field names and common values are vocabulary, and different models share habits.
  4. Learn your agents' habits. Do they copy the first link, the newest, or redo the work themselves? The same log supports different conclusions.
  5. Report the ceiling. "Untraceable from these logs" is a finding, not a failure.
  6. Measure who trusts a newcomer. An early bad tip took over some models completely and was ignored by others, and a late one was mostly ignored. Check outputs as well as sources.

What this does not show

  • The lab is offline and uses one narrow task. It is a controlled testbed, not a model of every swarm.
  • "Copied" means the agent was served that link before using it. When several posts hold identical links, the true source is not defined by text, so we only score attribution where each served copy is unique.
  • New runs use open models on one provider; earlier Claude runs are single-seed. Results are reported per model family, with seed-level confidence intervals.
  • Incident data is used as aggregates only, under the dataset owners' terms. Nothing here was run against anyone's live swarm.
